# Image Boot E2E Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement and verify each task.

**Goal:** Catch the reported failure where a client joins the hotspot but cannot reach the operations panel, using the built image in GitHub Actions.

**Architecture:** Boot an unchanged image through a disposable QEMU disk overlay using its shipped Raspberry Pi kernel, initramfs and Pi 4 device tree. Linux mac80211_hwsim provides isolated AP, upstream and client radios; a separate client network namespace exercises real hostapd, DHCP, DNS and HTTP through the actual firewall and OpenRC services. Collect diagnostics and fail the release gate on startup or client-flow failures.

**Tech Stack:** Alpine aarch64, QEMU raspi4b, OpenRC, mac80211_hwsim, Python standard library, GitHub Actions.

**Spec:** User request dated 2026-11-04: emulate the produced image on GitHub runners and add an end-to-end image test; existing architecture in `docs/design.md`.

## Global Constraints

- Test the generated disk image, including its embedded APK repositories and apkovl.
- No host block devices or physical CM5 writes from CI/testing code.
- Keep production images free of test accounts, test hooks and debug credentials.
- Use the image's kernel and userspace; label the Pi 4/QEMU boundary accurately.
- A passing emulation test does not qualify BCM2712/RP1 or a physical USB Wi-Fi adapter.
- Preserve diagnostics on failure; release publication must wait for the image test.

## Approach

A chroot service smoke test is faster but misses diskless boot and can inherit
an already configured host network. Full CM5 hardware emulation is unavailable
in QEMU. The selected engineering approach uses the supported Pi 4 machine with
the image's own compatible kernel, plus simulated radios. This is an
implementation choice within the requested image-testing scope.

## Review Focus

- DHCP succeeds but HTTP is unavailable: require client-side HTTP and live services.
- Missing kernel modules or offline packages: boot only from the image's embedded resources.
- Setup bypass or broken credential rotation: exercise authentication and setup gating over HTTP.
- Runtime crashes after successful OpenRC exit: inspect processes/listeners and repeat the client request.
- Test-specific changes masking a production error: keep instrumentation in the disposable guest and document it.
